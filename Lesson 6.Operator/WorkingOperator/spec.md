# Специфікація: WorkingOperator

Навчальний проєкт (Lesson 6 — перевантаження операторів, C#/.NET). Консольний застосунок.

## 1. Структура проєкту

```
WorkingOperator/                 ← корінь рішення (тут CLAUDE.md, spec.md, README.md)
├── WorkingOperator.slnx         ← рішення, містить один проєкт
├── README.md                    ← нотатки з налаштування Claude Code
├── WorkingOperator/
│   ├── WorkingOperator.csproj   ← конфігурація проєкту
│   ├── Program.cs               ← точка входу (top-level statements), демонстрація класів
│   ├── Device.cs                ← абстрактний базовий клас пристрою
│   ├── Laptop.cs                ← ноутбук, наслідує Device
│   ├── Phone.cs                 ← телефон, наслідує Device
│   └── Matrix.cs                ← клас для роботи з матрицями
├── bin/, obj/                   ← артефакти збірки (не редагувати)
└── .vs/                         ← службові файли Visual Studio
```

Батьківська папка `Lesson 6.Operator` і корінь git-репозиторію `Projects` містять інші уроки (`Lesson 1` … `Lesson 6`); вони не є частиною цієї специфікації.

- **Системні залежності:** лише .NET 9 runtime (або SDK для збірки).

## 4. Архітектурні рішення

- **Один проєкт, одна збірка.** Архітектурних шарів немає; вся логіка в одній збірці.
- **Точка входу — top-level statements** (`Program.cs`) без явного `Main`.
- **Кодування консолі — UTF-8** для вводу та виводу, бо тексти виводяться українською.
- **Ієрархія пристроїв:** `Device` — абстрактний базовий клас (`abstract`), створювати його напряму не можна. `Laptop` і `Phone` наслідують його.
  - `Device`: приватні поля з властивостями, що перевіряють значення (інкапсуляція). Поля: `Manufacturer`, `Model`, `Price`, `Processor`, `RamGb`, `StorageGb`. Конструктори `protected`: за замовчуванням і з шістьма параметрами. Перевизначено `ToString()`.
  - `Laptop`: додає `ScreenSizeInches`. Перевизначає `ToString()`, який додає діагональ до рядка `Device`.
  - `Phone`: додає `SimCount` і `CameraMegapixels`. Перевизначає `ToString()`, який додає SIM-картки і камеру до рядка `Device`.
  - Конструктори нащадків `public`, з параметрами базового класу плюс власні поля.
- **Клас `Matrix`:** прямокутна матриця `double[,]` з приватним полем лише для читання. Надає конструктор `(rows, cols)`, властивості `Rows` і `Cols`, індексатор `this[row, col]`, метод `Transpose()` і `ToString()`. Перевірка розмірів у конструкторі (має бути більше за нуль). Операторів (`+`, `*`) поки немає.
- **Перевантаження операторів поки не реалізовано** ні для `Device`, ні для `Matrix`. `ToString()` — перевизначення методу, а не оператор.
- **Тестів немає** (ні тестового проєкту, ні тестових фреймворків).
- **Конфігурація** (appsettings, DI, логування) відсутня — проєкт не потребує.

## 5. Стан реалізації

| Компонент | Стан |
|---|---|
| `Program.cs` | Створює `List<Device>` з двома телефонами (Samsung Galaxy S25, Motorolla Moto Signature) і двома ноутбуками (Dell Pro 16 Plus, ASUS Vivobook S16). Виводить їх через `ToString()`, розділяючи за типом (`is Phone`, `is Laptop`). |
| `Device.cs` | Готово: інкапсуляція, перевірка значень, `ToString()`. |
| `Laptop.cs` | Готово: поле `ScreenSizeInches`, `ToString()`. |
| `Phone.cs` | Готово: поля `SimCount`, `CameraMegapixels`, `ToString()`. |
| `Matrix.cs` | Готово: базові операції без арифметики. Не використовується в `Program.cs`. |
| Тести | Відсутні |

## 6. Команди

Запускати з папки, де лежить `WorkingOperator.slnx`:

- Збірка: `dotnet build WorkingOperator.slnx`
- Запуск: `dotnet run --project WorkingOperator/WorkingOperator.csproj`

Обидві команди перевірено: збірка успішна, 0 попереджень, 0 помилок. Запуск виводить чотири пристрої зі списку в `Program.cs`.
