# Специфікація: WpfAppImageView

Навчальний проєкт (Lesson 7 — форми, WPF/C#/.NET). Десктопний застосунок з одним вікном, що показує мініатюри зображень із вказаної папки.

## 1. Структура проєкту

```
WpfAppImageView/                      ← корінь рішення (тут CLAUDE.md, spec.md)
├── WpfAppImageView.slnx              ← рішення, містить один проєкт
├── .gitignore                        ← правила Visual Studio/.NET
├── CLAUDE.md                         ← інструкції для Claude Code
├── spec.md                           ← ця специфікація
├── WpfAppImageView/
│   ├── WpfAppImageView.csproj        ← конфігурація проєкту (WinExe, WPF)
│   ├── WpfAppImageView.csproj.user   ← порожні користувацькі налаштування Visual Studio
│   ├── App.xaml / App.xaml.cs        ← точка входу застосунку, StartupUri = MainWindow
│   ├── MainWindow.xaml               ← розмітка вікна: поле шляху, кнопка, галерея
│   ├── MainWindow.xaml.cs            ← уся логіка: читання файлів у потоці, показ мініатюр
│   ├── AssemblyInfo.cs               ← атрибут ThemeInfo (шаблонний)
│   ├── bin/, obj/                    ← артефакти збірки (не редагувати)
└── .vs/                              ← службові файли Visual Studio
```

Батьківська папка `Lesson 7.Forms` і корінь git-репозиторію `Projects` містять інші уроки (`Lesson 1` … `Lesson 7`, зокрема `MyWinForms`); вони не є частиною цієї специфікації.

## 2. Технології

| Параметр | Значення |
|---|---|
| Мова | C# |
| Фреймворк UI | WPF (`UseWPF=true`) |
| Платформа | .NET 9 для Windows (`net9.0-windows`) |
| Тип проєкту | Windows-застосунок (`OutputType=WinExe`) |
| SDK | .NET SDK 11.0.100 (використаний для збірки; сумісний з `net9.0-windows`) |
| Nullable-контексти | увімкнено (`Nullable`) |
| Неявні using | увімкнено (`ImplicitUsings`) |
| ОС розробки | Windows 11 |

Проєкт працює лише на Windows: WPF недоступний на Linux і macOS.

## 3. Залежності

- **NuGet-пакети:** відсутні. У `WpfAppImageView.csproj` немає `PackageReference`, а `obj/project.assets.json` не містить жодної бібліотеки.
- **Фреймворкові залежності:** вбудовані в .NET 9 для Windows, зокрема WPF (`System.Windows`, `System.Windows.Controls`, `System.Windows.Media.Imaging`), `System.IO`, `System.Diagnostics`, `System.Threading`.
- **Зовнішні сервіси, бази даних, мережа:** не використовуються.
- **Посилання на інші проєкти:** немає.
- **Системні залежності:** .NET 9 Desktop Runtime (або SDK для збірки).

## 4. Архітектурні рішення

- **Один проєкт, одна збірка, без шарів.** Немає окремих моделей, сервісів чи репозиторіїв.
- **Code-behind без MVVM.** Уся логіка знаходиться в `MainWindow.xaml.cs`. Прив'язка даних обмежена одним рядком: `ListBox` отримує `BitmapImage` через `{Binding}`.
- **Без DI і без конфігурації.** Залежностей між класами немає, налаштування не зберігаються.
- **Вибір папки вручну.** Користувач вписує шлях у `TextBox` (`txtPath`) і натискає кнопку. Діалогу вибору папки немає.
- **Асинхронність через `Task`:**
  - обробник `btnReadFile_Click` (`async void`, UI-потік) перевіряє, що папка існує (`Directory.Exists`), і чекає `await Task.Run(() => LoadImages(dirPath))`;
  - `LoadImages` (статичний, пул потоків) отримує список файлів через `Directory.GetFiles`, створює замороженні `BitmapImage` (`Freeze()`) для кожного з `DecodePixelWidth = 300` і `CacheOption.OnLoad`; не торкається елементів UI;
  - після `await` результат присвоюється `galleryList.ItemsSource` вже в UI-потоці. `Dispatcher.Invoke` не потрібен.
- **Розмір мініатюр задано двічі:** декодування до ширини 300 пікселів у коді, показ 150x150 з `UniformToFill` у XAML. Це зменшує пам'ять на великих зображеннях.
- **Галерея:** `ListBox` з `WrapPanel` як `ItemsPanel`, без горизонтальної прокрутки. Елементи — `Image` 150x150 з відступом 5.
- **Обробка помилок:** некоректні файли пропускаються порожнім `catch` без повідомлення. Помилка відсутньої папки показується через `MessageBox`.
- **Вимірювання часу:** `Stopwatch` у `LoadImages` рахує час, але результат не показується (виклик `MessageBox` закоментовано).
- **Тестів немає** (ні тестового проєкту, ні тестових фреймворків, ні аналізаторів понад стандартні попередження компілятора).

## 5. Стан реалізації

### Реалізовано
- Введення шляху до папки і перевірка її існування.
- Асинхронне (у фоновому потоці) завантаження зображень із папки.
- Показ мініатюр у `WrapPanel` з обрізанням до квадрата.
- Пропуск файлів, які не вдалося декодувати.

### Відомі обмеження і ризики
- **Фото не відображались через незаморожений `BitmapImage`** (виправлено: додано `Freeze()`). Перевірено лише збіркою; потрібен запуск з папкою зображень.
- **Немає захисту від повторного запуску.** Кожне натискання кнопки запускає нове завантаження. Результати кількох завантажень можуть перезаписувати одне одного в `galleryList.ItemsSource`.
- **Немає скасування.** Поточне завантаження неможливо перервати, наприклад коли користувач змінив шлях.
- **Фільтр файлів відсутній.** `Directory.GetFiles` повертає всі файли, включно з не-зображеннями; вони відсікаються лише через помилку декодування.
- **Підпапки не обходяться.** Читається тільки верхній рівень вказаної папки.
- **Винятки з `LoadImages` перехоплюються** в `btnReadFile_Click` і показуються в `MessageBox`. Без цього `try/catch` виняток в `async void` завершив би застосунок.
- **Жорстко закодовані рядки** українською мовою (`"Папку не знайдено"`, підпис кнопки). Локалізації немає.
- **Попередження компілятора:** чиста збірка (`--no-incremental`) має 0 попереджень і 0 помилок.
- **Невикористані `using` у `App.xaml.cs`:** `System.Configuration` і `System.Data` — залишки шаблону.
